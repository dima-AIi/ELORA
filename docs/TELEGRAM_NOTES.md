# Telegram — подробные разборы (ELORA)

Вынесено из `MEMORY.md`, чтобы тот оставался коротким. Здесь — истории грабель и порядок диагностики.
Общее: @elora_studio_bot (клиент), @elora_admin_bot (админ), Chat ID владельца `6097563857`.

## Почему клиенту не приходит подтверждение
- Telegram **запрещает боту писать первым**. Клиент получает сообщения только после того, как сам открыл бота и нажал Start. Поэтому чат обязан быть привязан **до** записи; иначе «Новая запись» клиенту законно не уходит.
- `Clients.TelegramChatId` появляется только после перехода по deep-link `?start=<код>` или после кнопки «📱 Отправить мой номер».
- Признаки в базе: `Bookings JOIN Clients` с пустым `TelegramChatId`; в `TelegramLinkCodes` `UsedAt IS NULL` = по ссылке не пошли.
- Разбор реального случая: запись #21 создана 20:21:37, чат клиента #7 привязан 20:21:45 — чата ещё не было, уведомление пропущено корректно. Плюс телефон, который владелец привязал кнопкой, уже принадлежал **другой** карточке клиента (#9).
- Диагностика на боевом: `tools/diag_client_notify.py`, `tools/_diag_prod_db.py`. Логов приложения на хостинге нет.

## Привязка чата — два пути
1. Deep-link `?start=<код>`: `GetOrCreateLinkCode` / `ConsumeLinkCode`, в коде лежит `BookingId` — после перехода бот сразу шлёт карточку той записи. Ссылка показывается, пока чат не привязан, в трёх местах: успех записи, `/my`, `/manage/{token}`. Ссылку выдаём всем: ник в форме к привязке отношения не имеет.
2. Изнутри бота: `/start` без кода при непривязанном чате (`IsChatBound`) шлёт reply-клавиатуру с кнопкой «📱 Отправить мой номер» (`TelegramButton.Contact`, `request_contact`). Контакт приходит **без поля `text`**, маршрут — `ITelegramUpdateHandler.HandleContactAsync` → `BindChatByPhone` (ищет по `NormalizePhone`, незнакомый номер заводит карточкой сразу с чатом, `Notes` = «Привязал чат в боте»). Форма кнопок — стендовый `GET /dev/bot/contact-keyboard`, отправка — `POST /dev/bot/contact`.

## Телефон — только один вид
`BookingRepository.NormalizePhone` сворачивает `8XXXXXXXXXX` и 10 цифр в `+7XXXXXXXXXX`. Номер, оканчивающийся теми же 10 цифрами под чужим кодом (`+999…`), **не** сворачивается. Если телефон хранится в разных видах, человек заводится двумя карточками, и чат остаётся на одной. `GetOrCreateClient` ищет клиента **только по телефону** — запись с тем же телефоном под другим именем перезаписывает `Name` и `TelegramNick` этой строки (так клиент #9 был переименован в «Проверка уведомления»). Дубликаты строк с одним телефоном ломают `FindClientId`: он вернёт первую, а чат может быть на второй.

## Кнопки
- Кнопка меню `web_app` («Сайт») на доставку не влияет, но уводит человека из чата, так и не нажав Start. `TelegramPollingService` при старте возвращает клиентскому боту меню команд (`ResetChatMenuButtonAsync`), в админке есть кнопка «Убрать кнопку «Сайт»».
- На сайт из чата ведёт подменю «🌐 Сайт студии» (`TelegramActions.Site` → `SendSiteAsync`): inline-кнопки-**ссылки** (`TelegramButton.Link`) на `/booking`, `/services`, `/price`, `/works`, `/#reviews`, `/contacts`, `/faq` и главную. Ссылка открывает браузер, чат остаётся на месте, привязка и Start не теряются. Форма — стендовый `GET /dev/bot/site-keyboard`.
- «Mini App» — админскому боту на `/admin`; клиентскому кнопки-сайта нет. Обе требуют HTTPS и токена.
- `TelegramBot.MessagePayload` выбирает reply-клавиатуру, если хоть одна кнопка `RequestContact`, иначе `inline_keyboard` — смешивать `request_contact` и inline в одной клавиатуре нельзя. `callback_data` ≤ 64 байт.

## Доставка и молчание
- `NotifyClientAboutNewBookingAsync` возвращает `null` (ушло) или причину словами: «клиент не открывал бота — чат Telegram не привязан», «в настройках выключены уведомления», «не задан токен клиентского бота», «Telegram не принял сообщение — возможно, клиент заблокировал бота». `NotifyNewBookingAsync` шлёт **сначала клиенту**, потом карточку админу, и вписывает в неё «✅ Подтверждение клиенту отправлено» либо «⚠️ Клиенту не ушло: … Позвоните». Порядок важен: иначе владелец уверен, что клиента предупредили, и не звонит.
- `SendToAdminAsync` имеет подстановку `AdminChannel = admin.IsConfigured ? admin : client` — из-за неё клиентский бот «выглядел живым», когда слал админские карточки.
- `SendMessageExAsync` отдаёт текст `description` из Telegram; `chat not found` переводится как «откройте бота и нажмите Start».
- `InviteBackAsync` возвращает причину и ставит `LastRemindedAt` только после успеха. `ClientsModel.DueWithoutTelegram` и дашбордный `TelegramBlockReason` показывают, кого придётся звонить.
- Ошибка `getUpdates` больше не молчит: ответ без `result` (типично — выставленный webhook, `409 Conflict`) логируется.
- `/book` передаёт `notifyClient: false` — мастер записи сам печатает «Вы записаны!». Смена статуса только через `BookingService.SetStatusAsync` (он же шлёт `NotifyStatusChangedAsync`).
- Ник — `Helpers/TelegramNick.Normalize` (`@nick` или `null`, принимает `t.me/…`), `Clients.TelegramNick`; пустое значение прежний ник не стирает.

## Почему уведомления молчат (чек-лист)
Нет токенов; снята галочка «Уведомления включены»; пуст Chat ID; человек ни разу не написал `/start`; чат не привязан; клиент заблокировал бота; выставленный webhook ломает long polling.

## Грабли транспорта
Адрес Bot API обязан быть абсолютным (иначе `NotSupportedException` роняет хост); общий `HttpClient.Timeout` убивает long polling (нужен отдельный клиент без таймаута).
