# ELORA — запуск в Visual Studio и публикация по ссылке

## 1. Запуск в Visual Studio

Открыть `ELORA.sln`.

В качестве Startup Project выбрать `ELORA.Web`.

Запустить:

- F5 — Debug;
- Ctrl+F5 — без Debug.

Visual Studio должна открыть браузер по URL из `Properties/launchSettings.json`, например:

`https://localhost:xxxx`

или

`http://localhost:xxxx`

Это нормальный режим разработки.

## 2. Открытие в браузере

Проект должен быть полноценным веб-приложением ASP.NET Core.

Он не должен зависеть от встроенного окна Visual Studio.

После запуска URL открывается в обычном Chrome/Edge.

## 3. Публичная ссылка

Чтобы сайт открывался по обычной ссылке вида:

`https://example-domain/...`

нужно опубликовать ASP.NET Core приложение на hosting, поддерживающий ASP.NET Core.

Общий процесс:

1. Visual Studio → Publish.
2. Выбрать подходящий hosting target.
3. Собрать Release.
4. Выполнить deployment.
5. Получить публичный HTTPS URL.
6. Открыть URL в обычном браузере.
7. Проверить booking, SQLite и Telegram.

## 4. SQLite при публикации

SQLite — файл.

Production hosting должен сохранять файл БД между перезапусками и redeploy, либо должен быть настроен persistent storage.

Нельзя размещать `elora.db` на полностью временной файловой системе и ожидать сохранения записей.

## 5. Конфигурация production

Не хранить секреты в коде.

Использовать:

- environment variables;
- secret configuration;
- User Secrets только для локальной разработки.

Параметры минимум:

- Telegram Bot Token;
- ключ AI-консультанта (`NVIDIA_API_KEY`);
- admin configuration;
- connection/database path при необходимости.

### Ключ AI-консультанта

Ключ задаётся **только на сервере** — в браузер он не попадает, потому что сайт
обращается к своему маршруту `POST /api/chat`, а уже тот идёт к модели.

- Fly.io: `fly secrets set NVIDIA_API_KEY=nvapi-...`
- Render: переменная `NVIDIA_API_KEY` в панели. В `render.yaml` она помечена
  `sync: false`, то есть значение вводится руками и в репозиторий не попадает.
- Модели задавать не обязательно: по умолчанию берётся цепочка `Ai:Models` из
  `appsettings.json`. Если нужно переопределить, есть две переменные:
  `NVIDIA_MODEL` — одна модель, `NVIDIA_MODELS` — цепочка через запятую
  (удобнее для секретов, где многострочные значения задавать неудобно).

**Важно: набор доступных моделей у каждого ключа свой.** Каталог `/v1/models`
общий и отдаёт около 80 моделей, но конкретный ключ может вызывать лишь часть —
на остальные приходит мгновенный `404 Not found for account`. Поэтому в настройках
задана цепочка: консультант перебирает модели по порядку, пока какая-нибудь не
ответит. После смены ключа **цепочку надо перепроверить** — доступные модели
могут отличаться. Скрипт для проверки: `tools/probe_nvidia_models.py`
(читает ключ из `NVIDIA_API_KEY`, сам ключ не печатает).

Локальный файл `.env` в образ не попадает (исключён в `.dockerignore`), а `Ai:ApiKey`
в `appsettings.json` остаётся пустым — ключ там хранить нельзя. Пока ключ не задан,
сайт работает, а консультант отвечает 503 с честным текстом вместо выдуманных ответов.

**Сменили ключ — перезапустите приложение:** ключ читается один раз при старте.

## 6. Проверка после публикации

Обязательно проверить по публичной ссылке:

- главную;
- mobile;
- услуги;
- наши работы;
- прайс;
- booking;
- создание записи;
- невозможность double booking;
- отмену;
- перенос;
- admin;
- Telegram;
- HTTPS;
- отсутствие broken images;
- отсутствие ошибок JavaScript;
- **секцию «Часто задаваемые вопросы» и AI-консультанта**: вопросы раскрываются,
  приветствие на месте, кнопка отправки неактивна при пустом поле, ответ приходит,
  а при ошибке появляется сообщение и кнопка «Повторить».
