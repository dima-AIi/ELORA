# ELORA — заметки по проекту

Студия красоты: ASP.NET Core 10 + Razor Pages + SQLite, фронт HTML/CSS/JS.
Код `D:\ELORA\ELORA\ELORA.Web`, доки `D:\ELORA\ELORA_agent_docs`, инструменты `D:\ELORA\tools`.
Боевой сайт `https://elora2026.runasp.net` (бесплатный хостинг MonsterASP).

## Правила
Код — только после прямого «давай». По-русски, коротко, опечатки не поправлять. Название только ELORA. Секреты не печатать нигде — ни в файлах, ни в командах, ни в логах.

## Окружение — грабли
- Сборка `bash tools/build.sh <аргументы dotnet>` (обёртка задаёт `APPDATA`; без него NuGet падает `Value cannot be null (Parameter 'path1')`). Smart App Control блокирует свежую `.dll` (`0x800711C7`) → `-p:AssemblyName=EloraRun<N>`. Прошлый стенд убить **до** сборки (иначе MSB3061): `MSYS_NO_PATHCONV=1 taskkill /PID <pid> /F`.
- Стенд: `Database__Path=…\elora.db ASPNETCORE_ENVIRONMENT=Production dotnet EloraRun<N>.dll --urls http://localhost:5087`, фоново и вне песочницы. Debug не копирует статику: `cp -r wwwroot/. bin/Debug/net10.0/wwwroot/`.
- `.cshtml`/`.css`/`.js` правятся живьём на стенде (`AddRazorRuntimeCompilation`), C# — пересборка; на боевом `.cshtml` в публикацию не попадают вовсе.
- `/dev/*` только в Development. Из песочницы не виден `api.telegram.org`; localhost — `curl --noproxy '*'`.
- **Текст боевых страниц искать только после `html.unescape`** — Razor отдаёт кириллицу числовыми ссылками. В layout нет `Request` — брать `ViewContext.HttpContext.Request`.
- **`hidden` перебивается авторским `display`** (`.choice { display: flex }` отменял браузерное правило) → в `site.css` объявлено своё `[hidden] { display: none !important; }`.
- **`X-Frame-Options: SAMEORIGIN` на страницу входа ставит сам Antiforgery**, когда страница отдаёт форму с токеном, — уже во время отрисовки. Из middleware не убрать, только `Response.OnStarting`. Источник ищется поиском строки `SAMEORIGIN` в UTF-16 по сборкам платформы (`Microsoft.AspNetCore.Antiforgery.dll`). Из-за этого панель-мини-приложение в Telegram Web (iframe) без снятия заголовка не откроется.
- **Smart App Control блокирует не каждую свежую сборку, а часть.** `EloraRun31` и `EloraRun33` запустились, `EloraRun32` и `EloraRun34` дали `0x800711C7` при трёх попытках подряд. Лечится новой цифрой в `AssemblyName`. Номер одноразовый: сборка с новым именем удаляет из `bin` файлы предыдущего.
- **Запуск стенда в фоне:** `&` внутри фоновой задачи не годится — процесс умирает вместе с задачей. Нужен `run_in_background` с сервером **в foreground**, без `&`. Убивать так: `netstat -ano | grep ":5087" | grep LISTENING` → `MSYS_NO_PATHCONV=1 taskkill /PID <pid> /F` (TaskStop иногда убивает обёртку, а `dotnet` остаётся и держит порт).
- Доступ в проверках — только через `tools/_admin_creds.js`: `ELORA_ADMIN_LOGIN/PASSWORD`, иначе `tools/_stand_admin.txt` (**строка 1 логин, строка 2 пароль**), иначе пароль панели. Печатать только источник, не значение.
- Стендовые базы: `tools/_test_db_53` (боевой контент + стендовый админ + фикстуры), `_test_db_54` (фото и награды очищены), `_test_db_55` (копия 53 под правки 26.09, `Site.WorkHours` уже новый). Проверки читают `ELORA_BASE` (по умолчанию боевой адрес), `ELORA_STAND_LOG`, `ELORA_ADMIN_PASSWORD`.
- Проверки без входа в админку не должны писать «ПЛОХО»: это `ПРОПУСК` и код выхода 0. `check_admin_settings.js` так и починен (читал пароль только из переменной окружения).

## Подробности по темам
- Telegram: два бота, привязка чата, доставка уведомлений — `TELEGRAM_NOTES.md`.
- Хостинг, выкладка, чего на боевом нет — `HOSTING_NOTES.md`.
- Админка, Mini App, право, картинки, «Мои записи» — `APP_NOTES.md`.
- Правки от 26.09.2026 (SEO, ошибки, заголовки, пометки, график) — `ELORA_agent_docs/FIXES_2026-09-26.md`.
- Устройство кода: `Endpoints/SeoEndpoints.cs` (robots + sitemap из `Site:PublicUrl`), `Middleware/SecurityHeaders.cs`, `Middleware/ErrorPages.cs`, `Helpers/PublicUrl.cs`, `Helpers/Demo.cs`.
- Выкладка и откат — `ELORA_agent_docs/VYKLADKA_I_OTKAT.md`. Одна команда: `bash tools/deploy_to_host.sh`; откат — `bash tools/rollback_host.sh` (источник `_upload_elora_prev`).
- **Откат «руками» через `sync_ftp.py` неполон.** `sync_ftp.py` считает файл залитым по размеру и хешу из `tools/_upload_state.json`; после отката в журнале под ключом `_upload_elora` остаются хеши новой сборки, и следующая выкладка пропустит файлы того же размера. `rollback_host.sh` снимает эту запись. Плюс ключ журнала — `D:/ELORA/_upload_elora`, а из Git Bash путь приходит как `/d/ELORA/_upload_elora` и превращается в `D:/d/ELORA/...` → нужен `cygpath -m` (проверено на копии журнала: точный путь снимает 1 запись, косой — 0).
- **Лучшая проверка бэкапа отката** — пробный прогон синхронизации из папки бэкапа: «залить 0, удалить 0» означает, что папка побайтово совпадает с хостингом. Надёжнее сверки хешей с журналом.

## Что осталось по технике
- **`Site.WorkHours` на боевом сайте надо заменить вручную** на «Пн–Сб 09:00 – 19:00, Вс — выходной» (`/admin/settings`). Код по умолчанию уже даёт правильное значение, но в базе лежит старое «Ежедневно 09:00 – 21:00», а база главнее.
- **Сборка к выкладке готова, на боевой не залита** — ждёт отмашки владельца. Папка `D:\ELORA\_upload_elora`, архив `D:\ELORA\elora_site.zip` (14 МБ, 430 файлов). План заливки: **13 файлов, 0 удалений** (`ELORA.Web.dll`, `.pdb`, `staticwebassets.endpoints.json`, `site.css` + `.br`/`.gz`, 4 картинки, `manifest.json` + `.br`/`.gz`). Бэкап отката `_upload_elora_prev` сверен с хостингом.
- **После заливки сразу проверить `manifest.json`:** отдаётся как `application/json`, а не `application/manifest+json` (спецификация советует второй). Браузеры принимают, Chrome ругается в консоль. Лечится MIME-картой в `web.config` на IIS или своим эндпоинтом.
- «Скидка 10% на первый визит» в блоке промо на главной — обещание скидки несуществующей студии, не тронуто (текст макета).
- `X-Powered-By`/`Server` от IIS убираются только в `web.config` хостинга, не трогал.
- Тестовые записи в `/admin/bookings` (удалять только закрытые). Если сайт когда-нибудь станет рабочим для настоящей студии — заполнить телефон, адрес, «Оператор данных», ИНН в `/admin/settings`; они же подставляются на `/privacy` как данные оператора персональных данных.
**Про локализацию данных:** сайт лежит на сервере в Германии, а форма собирает имя и телефон — это нарушение ч. 5 ст. 18 152-ФЗ для того, кто обрабатывает данные клиентов. Но владелец — студент, ИП нет, сайт — портфолио и учебный проект, настоящих клиентов нет, поэтому **сейчас это не срочно** и денег не требует: уведомление в РКН не нужно, переезд откладывается до момента, когда сайт начнёт принимать реальных клиентов. Дело не в VPN владельца, а в стране сервера.
