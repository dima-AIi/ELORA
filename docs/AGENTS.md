# AGENTS.md — правила для AI-кодинг-агента ELORA

## Перед началом

Сначала полностью прочитай все `.md` документы в этой папке и сопоставь их между собой.

После этого сразу начинай реализацию. Не жди отдельного подтверждения очевидных технических решений.

## Главные правила

- Проект называется **ELORA**.
- Не использовать старое название BookFlow в интерфейсе, namespace/названиях проекта, заголовках документации и пользовательских текстах.
- Работать в ASP.NET Core + C# в Visual Studio.
- Предпочтительно Razor Pages.
- SQLite остаётся основной БД MVP.
- Frontend: HTML + CSS + vanilla JavaScript.
- Не заменять реальную функциональность статическим mockup.
- Не добавлять технологии ради «современности».
- Не добавлять функции вне Product Scope без необходимости.
- Не удалять существующую бизнес-логику ради визуального соответствия.
- Не менять дизайн на собственный: визуальный эталон — четыре изображения ELORA.
- После каждого крупного этапа выполнять build и проверять основной сценарий.
- Проверять desktop и mobile.
- Все формы должны иметь validation, loading, error и success states.
- Секреты Telegram не хранить в исходниках.

## Визуальное правило

Референсы не являются приблизительной идеей. Они задают:

- композицию;
- визуальную иерархию;
- размеры и соотношения блоков;
- цвета;
- скругления;
- типографику;
- плотность контента;
- desktop/mobile поведение.

Нельзя «улучшать» дизайн так, чтобы он перестал быть похож на референс.

## Дополнительные страницы

В header присутствуют «О нас» и «Контакты». Их можно реализовать как отдельные страницы `/about` и `/contacts` в той же дизайн-системе, если эти разделы не представлены отдельными блоками на главной.

Не добавлять большие новые секции на главную, отсутствующие в референсах, только ради количества.

## Запуск и публикация

В Visual Studio должен работать запуск через F5 с открытием браузера.

Также проект должен быть publish-ready: `dotnet publish` должен создавать deployable output, а production-конфигурация должна поддерживать публичный URL.
