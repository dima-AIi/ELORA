# ELORA — пошаговое развёртывание

Инструкция «делай по порядку». Хостинг — **Fly.io**: там деплой идёт прямо из
локальной папки, Git не нужен, постоянный том под базу стоит копейки, а
`fly.toml` в проекте уже настроен.

Всё, что нужно от вас — аккаунт, установленный `flyctl` и несколько команд.
Docker на машине **не нужен**: Fly собирает образ на своей стороне.

---

## Шаг 0. Что понадобится

| Что | Зачем |
| --- | --- |
| Аккаунт Fly.io | бесплатно, нужна привязка карты (том и машина стоят центы) |
| `flyctl` | программа для деплоя, ставится одной командой |
| Ключ NVIDIA (`nvapi-...`) | уже есть, лежит в `ELORA.Web/.env` |
| Пароль для админки | придумайте свой — стандартный знают все |

Токены Telegram нужны, только если хотите уведомления о заявках и бота.
Без них сайт работает полностью, а бот просто не запускается.

## Шаг 1. Установить flyctl

Windows (PowerShell):

```powershell
iwr https://fly.io/install.ps1 -useb | iex
```

Закройте и откройте терминал заново, затем проверьте:

```powershell
fly version
```

## Шаг 2. Войти в аккаунт

```powershell
fly auth login
```

Откроется браузер — войдите или зарегистрируйтесь, затем вернитесь в терминал.

## Шаг 3. Перейти в папку приложения

Все команды дальше выполняются **из папки с `Dockerfile` и `fly.toml`**:

```powershell
cd D:\ELORA\ELORA\ELORA.Web
```

## Шаг 4. Создать приложение

```powershell
fly launch --no-deploy
```

- На вопрос про имя оставьте `elora`. Если имя занято, Fly предложит другое —
  согласитесь, оно станет частью адреса сайта.
- Регион: `ams` (Амстердам) уже прописан в `fly.toml`.
- **На предложение создать Postgres ответьте «нет»** — сайт использует SQLite.
- На вопрос про настройку/перезапись `fly.toml` отвечайте «нет»: файл уже готов.

## Шаг 5. Создать постоянный том под базу

**Без этого шага все записи клиентов исчезнут при первом же обновлении сайта** —
база будет жить внутри контейнера и обнулится.

```powershell
fly volumes create elora_data --size 1 --region ams
```

На вопрос о подтверждении — согласиться. Том 1 ГБ, этого с запасом.

## Шаг 6. Задать секреты (до первого запуска!)

Это самый важный шаг. Секреты не попадают ни в файлы, ни в репозиторий, ни в образ.

**6.1. Пароль администратора — обязательно.** Логин и пароль создаются при первом
запуске на пустой базе. Значения по умолчанию (`admin` / `elora2026`) знает любой,
кто читал исходники, поэтому на публичном сайте их быть не должно.

```powershell
fly secrets set ELORA_ADMIN_LOGIN="admin" ELORA_ADMIN_PASSWORD="ВашНадёжныйПароль"
```

> Пароль задаётся **только до первого запуска**. Если приложение уже стартовало
> с базой по умолчанию, эта переменная не применится — придётся сменить пароль
> в админке в разделе «Профиль».

**6.2. Ключ AI-консультанта.** Возьмите значение `NVIDIA_API_KEY` из файла
`D:\ELORA\ELORA\ELORA.Web\.env`:

```powershell
fly secrets set NVIDIA_API_KEY="nvapi-..."
```

**6.3. Telegram — по желанию.** Задаются только **токены ботов**:

```powershell
fly secrets set Telegram__BotToken="<токен клиентского бота>"
fly secrets set Telegram__AdminBotToken="<токен админского бота>"
```

Секреты можно объединить в одну команду:
`fly secrets set A="1" B="2" C="3"`.

> **Номер чата администратора (`Telegram.AdminChatId`) секретом задать нельзя** —
> он хранится в базе, а не в настройках приложения. Его нужно вписать после
> первого входа в админку, в разделе **Настройки**. Если оставить пустым,
> уведомления о новых заявках просто не будут отправляться: бот напишет об этом
> в лог при старте.

## Шаг 7. Опубликовать

```powershell
fly deploy
```

Сборка идёт на стороне Fly, занимает несколько минут. В конце появится ссылка.

## Шаг 8. Открыть сайт

```powershell
fly open
```

Адрес будет вида `https://<имя>.fly.dev`.

## Шаг 9. Задать публичный адрес сайта

Нужно для кнопки Mini App в Telegram: она включается только по HTTPS, а
приложение должно знать свой публичный адрес.

```powershell
fly secrets set Site__PublicUrl="https://<ваш-адрес>.fly.dev"
```

После этого приложение перезапустится само.

## Шаг 10. Проверить, что всё работает

1. **Главная страница** открывается по HTTPS, картинки на месте.
2. **Секция «Частые вопросы»** — вопросы раскрываются.
3. **AI-консультант**: спросите «Сколько стоит маникюр?» — должен ответить
   по делу за пару секунд. Спросите «Какая ты модель?» — должен вежливо уйти
   от ответа.
4. **Админка**: `https://<адрес>/admin/login` — войдите с логином и паролем
   из шага 6.1. Проверьте именно **свои** логин и пароль: если они не подойдут,
   значит секреты не доехали, и сайт остался на `admin` / `elora2026`. Это не
   теория — пара проверяется скриптом:
   ```powershell
   cd D:\ELORA\tools
   python check_admin_env.py https://<адрес>
   ```
   Он пробует оба набора и печатает, какой пустил. Правильный ответ: свои —
   «вход выполнен», `admin` / `elora2026` — «не пустило».
5. **Если нужны уведомления в Telegram** — в админке откройте **Настройки** и
   впишите номер чата администратора. Бот не может задать его сам: секретом этот
   номер не передаётся.
6. **Здоровье службы**:
   ```powershell
   fly status
   fly logs
   ```
   В логах не должно быть ошибок, а `fly status` — показывать машину в состоянии
   `running` с прошедшей проверкой `/healthz`.

### Если консультант ответил «сервис перегружен»

Это **нормальная** ситуация, а не поломка сайта. Модели работают на бесплатном
тарифе, и он регулярно отвечает «Service temporarily overloaded». Что делает сайт:

1. повторяет запрос к той же модели (до трёх раз — она отвечает за пару секунд,
   поэтому повторы дешёвые);
2. если не помогло — берёт следующую модель из цепочки;
3. если и там перегрузка — честно говорит об этом посетителю и предлагает телефон.

Посмотреть, что происходило, можно так:

```powershell
fly logs
```

В строках с `AI-консультант` видно, какая модель ответила и почему не вышло.
Если перегрузка повторяется слишком часто, можно поменять порядок моделей
секретом `NVIDIA_MODELS` (через запятую) — тогда пересобирать не нужно:

```powershell
fly secrets set NVIDIA_MODELS="nvidia/nemotron-3-super-120b-a12b,meta/muse-glimmer-30b"
```

> Список доступных моделей у каждого ключа свой: каталог общий, а доступ — нет.
> Модель, которой нет у ключа, отвечает «Not found for account». Проверить, что
> доступно именно вашему ключу, можно скриптом `tools/probe_nvidia_models.py`.

## Шаг 11. Про защиту админки

Страница `/admin/login` доступна всем — так устроено приложение, и спрятать её
настройкой нельзя. Что уже сделано на стороне кода:

- пароль хранится хешем, не в открытом виде;
- cookie админки получает `secure`, `httponly` и `samesite` за HTTPS;
- формы защищены antiforgery-токеном;
- вся папка `/admin` закрыта авторизацией, открыт только вход.

Что нужно от вас: **надёжный пароль** из шага 6.1, не короче 12 символов.
Не оставляйте `elora2026` — он написан в исходниках.

Если нужна защита строже (ограничение по IP, двухфакторный вход) — это отдельная
доработка, сейчас её в проекте нет.

## Что уже готово в проекте

Проверено перед публикацией:

- **Порт.** Приложение слушает `0.0.0.0` и порт из переменной `PORT` — проверено
  запуском опубликованной сборки: `Now listening on: http://0.0.0.0:8090`.
- **Доверенный прокси.** Заголовок `X-Forwarded-Proto` обрабатывается, cookie
  админки получает признаки `secure`, `httponly`, `samesite` только за HTTPS.
- **Dockerfile** — двухэтапная сборка, `UseAppHost=false`, рантайм-образ без SDK.
- **`.dockerignore`** исключает `App_Data/`, `*.db` и `.env` — ключ и рабочая база
  в образ не попадают (проверено: в публикации ни ключа, ни базы нет).
- **Постоянный том** смонтирован в `/data`, путь задан через `Database__Path`.
- **`/healthz`** отвечает 200 и подключён как проверка работоспособности.
- **`min_machines_running = 1`** — фоновые службы (напоминания клиентам, приём
  сообщений Telegram) не засыпают.
- **Релизная сборка** чистая: 0 ошибок, 0 предупреждений.

## Частые проблемы

**«Сайт открывается, но консультант отвечает, что не подключён»**
Не задан `NVIDIA_API_KEY`. Проверьте: `fly secrets list`, затем `fly logs` —
там будет строка про отсутствующий ключ.

**«После деплоя пропали все записи»**
Не создан том (шаг 5) или не задан `Database__Path`. Без тома база живёт внутри
контейнера. Проверьте, что в `fly.toml` есть блок `[[mounts]]`.

**«Не могу войти в админку»**
Если `ELORA_ADMIN_PASSWORD` задан уже после первого запуска, он не применяется:
администратор создаётся один раз на пустой базе. Удалите том и разверните заново
(данные пропадут) либо смените пароль в админке.

**«Кнопка Mini App в Telegram не появляется»**
Не задан `Site__PublicUrl` (шаг 9) — без него приложение не знает свой адрес по
HTTPS и отдаёт обычную ссылку вместо кнопки.

**«Проверка работоспособности не проходит, машина перезапускается»**
Смотрите `fly logs`. Частая причина — недоступная база или ошибка в настройках.
Проверка ждёт 200 от `/healthz`, который отдаётся только при живой базе.

**Деплой зависает на сборке**
Первая сборка скачивает образы .NET — это долго. Если больше 10 минут, проверьте
`fly logs` и наличие свободного места у удалённого сборщика.

## Альтернатива: Render

В корне проекта лежит `render.yaml` — конфигурация для Render. Отличия:

- Render разворачивает **из Git-репозитория**, поэтому проект сначала нужно
  закоммитить и запушить на GitHub/GitLab.
- Постоянный диск доступен **только на платном тарифе** (`starter` и выше).
  На бесплатном база обнуляется при каждом деплое — для реального сайта не годится.
- Секреты задаются в панели: `NVIDIA_API_KEY`, `ELORA_ADMIN_LOGIN`,
  `ELORA_ADMIN_PASSWORD`, `Site__PublicUrl`, при необходимости токены Telegram.
