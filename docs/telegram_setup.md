# Подключение Telegram к сайту ELORA — пошагово

В проекте работают **два бота**. Это не прихоть: меню команд и кнопка Mini App в Telegram
настраиваются **на бота, а не на пользователя**. С одним ботом клиенты видели бы в меню
команды администратора, а администратор — клиентские.

| Бот | Кому | Зачем | Где упоминается |
|---|---|---|---|
| **@elora_studio_bot** | клиентам | запись, «Мои записи», перенос, отмена, напоминания | публично: сайт, подтверждение записи |
| **@elora_admin_bot** | администратору | сводки дня и недели, клиенты, статистика, карточки записей | нигде не публикуется |

Что уже готово в проекте (писать код не надо, только настроить):

- `Services/Telegram/TelegramBot.cs` — транспорт одного бота (sendMessage, кнопки, getUpdates).
- `Services/Telegram/TelegramBots.cs` — два бота: клиентский и админский.
- `Services/TelegramService.cs` — сценарии: что и кому отправляем, через какого бота.
- `Background/TelegramPollingService.cs` — long polling; регистрируется дважды, по экземпляру
  на бота. Публичный адрес не нужен, работает и локально, и на хостинге.
- `Background/ClientBotHandler.cs` + `ClientBookingWizard.cs` — клиентский бот: привязка чата,
  список записей, перенос и отмена кнопками, новая запись целиком в чате.
- `Background/AdminBotHandler.cs` — админский бот: `/today`, `/week`, `/clients`, `/stats`.
- `Services/ReminderService.cs` + `ReminderBackgroundService` — напоминания за N часов до визита.
- `Services/ClientReminderService.cs` — приглашение вернуться тем, кто давно не был.
- `/admin/settings` — страница, где всё это включается.

**Главное правило:** токены ботов НЕ лежат в коде и НЕ хранятся в базе. Только user-secrets
или переменные окружения. В `appsettings.json` они пустые — так и должно быть.

## Шаг 1. Создать двух ботов (5 минут, в Telegram)

1. Открой Telegram (телефон или десктоп).
2. В поиске набери **`@BotFather`**. Открой того, у кого синяя галочка.
3. Нажми **Start**, затем напиши `/newbot` и отправь.
4. BotFather спросит **имя бота** — то, что увидят люди. Для первого напиши
   `ELORA — студия красоты` и отправь.
5. Теперь спросит **username** — латиницей, обязательно заканчивается на `bot`. Например
   `elora_studio_bot`. Если занято — придумай другой.
6. В ответ придёт строка вида:
   > Use this token to access the HTTP API:
   > **8123456789:AAH-xxxxxxxxxxxxxxxxxxxxxxxxxxx**
7. **Нажми на эту строку** — Telegram скопирует токен в буфер. Токен выглядит как число,
   двоеточие, потом ~35 символов.
8. **Повтори шаги 3–7 ещё раз** для второго бота: имя `ELORA Администратор`,
   username вида `elora_admin_bot`.

Итого у тебя на руках два токена: клиентский и админский.

⚠️ Токен — это пароль от бота. Кому попадёт — тот сможет писать от его имени и читать
переписку. Никому не пересылай. Если утёк — в BotFather `/revoke` и получишь новый.

### Приятные мелочи (по желанию, в том же @BotFather)

| Команда | Что делает |
|---|---|
| `/setdescription` | описание бота на странице «Что умеет» |
| `/setuserpic` | аватарка бота |
| `/setname` | имя бота |
| `/setcommands` | список команд в меню. Сайт задаёт его сам при запуске, но можно и вручную |

## Шаг 2. Положить оба токена в проект

Открой терминал в папке проекта:

```
cd D:\ELORA\ELORA\ELORA.Web
dotnet user-secrets set "Telegram:BotToken" "8123456789:AAH-xxxxxxxxxxxxxxxxxxxxxxxxxxx"
dotnet user-secrets set "Telegram:AdminBotToken" "8536276031:AAF-xxxxxxxxxxxxxxxxxxxxxxxxxxx"
```

Вместо примеров — свои токены из шага 1, **вместе с кавычками**.

Куда они попали: `%APPDATA%\Microsoft\UserSecrets\elora-web-secrets-2026\secrets.json` — это
вне папки проекта, поэтому в git и в публикацию они не попадут.

Проверить:

```
dotnet user-secrets list
```

Должны появиться две строки: `Telegram:BotToken = ...` и `Telegram:AdminBotToken = ...`.

**После этого сайт нужно перезапустить** — токены читаются при старте. (Могу сделать я.)

Альтернатива без user-secrets — переменные окружения:

```
set Telegram__BotToken=8123456789:AAH-xxxxxxxxxxxxxxxxxxxxxxxxxxx
set Telegram__AdminBotToken=8536276031:AAF-xxxxxxxxxxxxxxxxxxxxxxxxxxx
```

(обрати внимание: двойное подчёркивание `__` вместо двоеточия)

## Шаг 3. Узнать свой Chat ID

Без него админский бот не пустит никого, а клиентский не будет знать, куда слать
уведомления о новых записях.

1. В Telegram открой `https://t.me/<username_админского_бота>`.
2. Нажми **Start**. Бот ответит: «в админке не указан Chat ID администратора» и **покажет
   твой Chat ID** — можно скопировать прямо оттуда. Это самый быстрый способ.
3. Альтернативы:
   - скриптом: `python D:\ELORA\tools\telegram_check.py <токен>` — напечатает имя бота и все
     чаты, которые ему писали;
   - через бота `@userinfobot` — напиши ему что угодно, он ответит своим ID.

Свой личный ID — обычно 9–10 цифр, может начинаться с минуса (если это группа).

**Важно:** в клиентском боте тоже нужно нажать Start — иначе клиентский бот не сможет
прислать тебе тестовое сообщение. Достаточно открыть `https://t.me/<username_клиентского_бота>`
и нажать Start.

## Шаг 4. Включить в админке сайта

1. Открой **http://localhost:5080/admin** и войди: логин **admin**, пароль **elora2026**.
2. Слева выбери раздел **Настройки** (`/admin/settings`).
3. Найди блок **«Telegram-боты»**. Справа от заголовка два бейджа:
   **«клиентский: токен задан»** и **«админский: токен задан»**. Если какой-то красный —
   вернись к шагу 2, токен не подхватился.
4. Нажми **«Проверить токены и подтянуть имена»** — сайт сходит в Telegram и сам подставит
   оба username в поля «Имя клиентского бота» и «Имя админского бота».
5. В поле **«Chat ID администратора»** впиши свой ID из шага 3.
6. **«Напомнить за, часов»** — оставь `24` (или поставь сколько нужно, от 1 до 168).
7. Поставь галочку **«Уведомления включены»** — без неё оба бота молчат.
8. Поставь галочку **«Сообщать администратору о каждой новой записи»**.
9. Нажми **Сохранить** (под блоком Telegram).

### Проверка

Две кнопки:

- **«Тест: администратору»** — сообщение должно прийти от **админского** бота;
- **«Тест: клиентский бот»** — от **клиентского**.

Не пришло — смотри таблицу «Если не работает» ниже.

### Блок «Возврат клиентов»

Там одно поле: **«Считать нормой, недель между визитами»** (по умолчанию 3).
Клиент попадает в список «пора напомнить», если с последнего *завершённого* визита прошло
больше этого срока и новой записи у него нет.

### Ссылка на бота в подвале сайта

В том же разделе, блок **«Контакты и часы работы»**, поле **«Telegram (ссылка)»** — впиши
`https://t.me/<username_клиентского_бота>` и нажми **Сохранить**. Тогда иконка Telegram
в подвале и на странице «Контакты» будет вести на клиентского бота.

## Шаг 5. Проверить клиентский путь (как это увидит клиентка)

1. Открой **http://localhost:5080/booking**, выбери услугу, мастера, дату и время.
2. На шаге **7 «Telegram — по желанию»** впиши любой ник или телефон (поле просто фиксирует
   желание получать уведомления).
3. Заверши запись. На странице подтверждения появится кнопка
   **«Открыть Telegram-бота»** — она ведёт по ссылке вида `t.me/<бот>?start=Ab12Cd34`.
4. Нажми её → в Telegram нажми **Start** → бот ответит **«✅ Telegram подключён!»**.
5. Напиши боту `/my` — пришлёт список записей с кнопками. `/book` — новая запись прямо в чате.

Ссылка с кодом одноразовая: второй раз тот же код не сработает, бот скажет «Ссылка уже
использована или устарела».

## Что умеют боты после настройки

### Клиентский бот (@elora_studio_bot)

**Клиенту:**
- ✅ подтверждение подключения;
- `/my` — записи с кнопками **ℹ️ Детали / 🕒 Перенести / ❌ Отменить**;
- перенос — выбор мастера, дня и времени **кнопками в чате**, без выхода на сайт;
- отмена — с подтверждением (одним нажатием не отменяется, отмена необратима);
- `/book` — новая запись целиком в чате: направление → услуга → мастер → день → время →
  имя → телефон → комментарий → подтверждение;
- напоминание за N часов до визита, тоже с кнопками;
- уведомление, если запись отменили;
- 💫 приглашение вернуться, если давно не были.

**Администратору (на твой Chat ID):**
- 🆕 «Новая запись» — сразу при оформлении, с кнопками ✅ Подтвердить / 🕒 Перенести / ❌ Отменить;
- ❌ «Запись отменена» (кем именно);
- 🕒 «Запись перенесена» — с новым временем;
- напоминание о визите за N часов, если клиент не подключил Telegram.

### Админский бот (@elora_admin_bot)

- `/today` — сегодняшние визиты по времени, с кнопками по каждой записи;
- `/week` — ближайшая неделя: загрузка и выручка по дням;
- `/clients` — поиск клиента по имени или телефону (можно просто написать имя);
- `/stats` — выручка, визиты, средний чек за текущий месяц;
- карточка записи с кнопками **✅ Подтвердить / 🕒 Перенести / ❌ Отменить / 💬 Написать**;
- «💬 Написать» — сообщение уходит клиенту **через клиентский бот**, чтобы для клиента оно
  пришло от знакомого бота студии.

Постороннему чату админский бот отвечает «Этот бот только для администратора студии»
и не показывает ничего.

## Раздел «Клиенты» в админке

Адрес `/admin/clients`. Раньше клиентов было видно только через записи, по одной.

**Список:**
- четыре плитки сверху: всего клиентов, сколько подключено к боту, сколько оставили за всё
  время, сколько «пора напомнить»;
- блок **«Пора напомнить»** — те, кто был больше N недель назад и не записан. У кого
  подключён Telegram — кнопка **«Пригласить»**, у кого нет — пометка «звонок» и кликабельный
  телефон. Есть кнопка **«Пригласить всех, кто в боте»**;
- таблица всех клиентов с поиском по имени и телефону: визиты, последний визит, ближайшая
  запись, сколько оставил, заметка.

**Карточка клиента** (`/admin/client/<id>`): три плитки с числами, контакты, статус Telegram,
ближайшая запись, когда приглашали вернуться, история всех записей и заметка администратора
(видна только в админке — клиент её не получает).

Приглашение уходит только тем, у кого подключён Telegram, и отметка ставится **после**
успешной отправки. Повторно тому же человеку бот не напишет две недели — иначе напоминания
превратились бы в спам.

## Вход в панель из Telegram (Mini App)

После публикации админку можно открывать прямо в Telegram — кнопкой меню рядом с полем ввода
или кнопкой **«🖥 Панель управления»** в ответе бота. Второй панели нет: открывается та же
`/admin`, что и в браузере.

**Как это работает.** Telegram отдаёт странице подписанную строку `initData`. Сайт проверяет
подпись **токеном админского бота** (ключ считается как `HMAC_SHA256("WebAppData", токен)`,
затем `HMAC_SHA256(ключ, строка данных)`), сверяет `user.id` с «Chat ID администратора»
и только тогда выдаёт cookie админки. Токен в браузер не попадает — страница присылает
только подпись, подделать её без токена нельзя.

**Пароль остаётся рабочим** — он запасной вход: если бот не настроен, Telegram недоступен
или ты за компьютером. Ничего не сломалось.

**Что нужно, чтобы кнопка появилась:**
1. сайт опубликован по **HTTPS** — Telegram не открывает мини-приложения по http;
2. в «Настройки» → `Site:PublicUrl` вписан этот адрес (например `https://elora.fly.dev`);
3. задан «Chat ID администратора» — по нему сайт узнаёт, что вошёл именно ты;
4. сайт перезапущен: кнопка меню ставится один раз при старте.

Пока адрес начинается на `http`, в боте показывается обычная ссылка, а не Mini App —
это сделано специально, чтобы кнопка не открывала пустой экран.

Проверка на месте, без публикации: `node D:\ELORA\tools\verify_miniapp.js shots_miniapp`
(стенд собирает такую же подписанную строку и прогоняет весь путь — вход, подделка подписи,
чужой аккаунт, пустые данные, вход по паролю).

## Если не работает

| Симптом | Причина и что делать |
|---|---|
| Бейдж «токен не задан» | Токен не подхватился. Проверь `dotnet user-secrets list` и **перезапусти сайт**. |
| Админский бот отвечает «не указан Chat ID администратора» | Он показывает твой ID — скопируй его в «Настройки» → «Chat ID администратора» и напиши боту `/start`. |
| Админский бот пишет «только для администратора» | Chat ID в настройках не совпадает с твоим. Скопируй ID из сообщения бота в настройки. |
| «Тест: администратору» пишет, что Chat ID пустой | Заполни «Chat ID администратора» и нажми Сохранить. |
| Тест не приходит | Ты не нажал Start **у этого бота**. У клиентского и админского бота Start нажимается отдельно. |
| В логе `Unauthorized` | Токен скопирован не целиком или отозван. Скопируй заново из @BotFather. |
| Уведомления не идут, хотя тест работает | Снята галочка «Уведомления включены». Поставь и сохрани. |
| Бот не отвечает на команды, хотя тест проходит | Сайт должен быть запущен — long polling живёт внутри приложения. Проверь в логе строку «бот готов к работе: @…». |
| В логе «превысил таймаут 20 с» пачками | Общий таймаут HttpClient снова задан. Он должен быть `Timeout.InfiniteTimeSpan`, а лимит — на каждый вызов. |
| Кнопка «Перенести» у админа ведёт на `localhost` | Заполни `Site:PublicUrl` реальным адресом сайта (для хостинга). |
| Приглашение не уходит | У клиента не подключён Telegram, или он заблокировал бота. Админка скажет, что именно. |
| В Telegram открылась форма с паролем, а не панель | Три причины по очереди: сайт по http (нужен HTTPS), пустой `Site:PublicUrl` или твой Telegram id не равен «Chat ID администратора». Введи пароль — вход остаётся рабочим. |
| «Вход через Telegram отклонён: подпись не совпадает» | Открыли панель не из Telegram (например, скопировали ссылку в браузер) или страница пролежала открытой больше суток. Открой панель кнопкой в боте заново. |
| «Этот Telegram-аккаунт не привязан к админ-панели» | Подпись верна, но это не аккаунт администратора: сверь «Chat ID администратора» в настройках с тем, кто открывает панель. |

## Важно перед публикацией на хостинге

1. Оба токена — **секреты хостинга**: `Telegram__BotToken` и `Telegram__AdminBotToken`.
   В `appsettings.Production.json` они пустые — так и оставить.
2. `Site:PublicUrl` сейчас `http://localhost:5080`. Вписать реальный адрес (например
   `https://elora.fly.dev`) — иначе в кнопке «Перенести» уйдёт ссылка на localhost.
3. Long polling публичного URL не требует, поэтому webhook настраивать не нужно.
4. Кнопка Mini App в админском боте и вход без пароля **уже сделаны в коде**. Осталось только
   вписать реальный адрес в `Site:PublicUrl` и перезапустить сайт — тогда Telegram начнёт
   открывать панель внутри себя. До этого там обычная ссылка на `/admin`.

## Одно честное ограничение

В схеме есть колонка `Masters.TelegramChatId`, но в коде `GetMasterChatId()` пока возвращает
`null` — то есть **персональных уведомлений мастерам нет**, всё идёт администратору.
Если нужно, чтобы каждая мастерица получала свои записи — скажи, добавлю поле в админку
«Мастера» и допишу отправку.
