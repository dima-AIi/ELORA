# ELORA — Техническое описание дизайна сайта по 4 референсам

## Назначение документа

Этот документ предназначен для AI-агента-разработчика.  
Задача агента — реализовать сайт **ELORA** максимально близко к четырём предоставленным референсным изображениям.

**Критическое правило:** изображения являются визуальным эталоном. Не придумывать новый дизайн и не упрощать композицию без необходимости. Нужно воспроизвести структуру, визуальную иерархию, пропорции, отступы, карточки, изображения, типографику и адаптивное поведение, показанные на референсах.

Референсы:

1. `ELORA_1_desktop_top.png` — верхняя часть Desktop.
2. `ELORA_2_desktop_bottom.png` — нижняя часть Desktop.
3. `ELORA_3_mobile_top.png` — верхняя часть Mobile.
4. `ELORA_4_mobile_bottom.png` — нижняя часть Mobile.

---

# 1. Общая концепция сайта

ELORA — современный премиальный сайт бьюти-студии/мастера с онлайн-записью.

Основные услуги:

- Маникюр
- Педикюр
- Ресницы
- Брови
- Волосы
- Тату

Главная цель сайта — быстро показать услуги, работы, цены, преимущества и привести пользователя к записи.

## Визуальное направление

Стиль:

- premium beauty;
- editorial / luxury;
- мягкий минимализм;
- светлая кремово-пудровая палитра;
- тёплые фотографии;
- тонкие рамки;
- большие скругления;
- элегантная serif-типографика для крупных заголовков;
- аккуратный sans-serif для интерфейсного текста;
- тёмно-коричневые CTA;
- много свободного пространства;
- отсутствие визуального шума.

Основные цвета приблизительно:

- фон: `#F7EEE8` / тёплый ivory;
- поверхности: `#FFF8F3`;
- тёмный текст: `#3D2923`;
- основной CTA: тёмный шоколадно-коричневый;
- акцент: пыльно-розовый / peach;
- нижний pricing-блок: глубокий коричневый;
- границы: полупрозрачный тёплый beige.

Цвета не должны выглядеть кислотными или слишком насыщенными.

# 26. Адаптивность

Необходимо реализовать два явно выраженных состояния.

## Desktop

Примерная ширина:

1440px и выше.

Особенности:

- широкий центральный контейнер;
- горизонтальная навигация;
- Hero в две колонки;
- Services в один ряд;
- Portfolio в один ряд;
- Pricing в три колонки;
- Booking steps в один ряд;
- Reviews в четыре колонки.

## Tablet

Плавная адаптация:

- уменьшается количество колонок;
- сокращаются отступы;
- карточки переносятся;
- текст остаётся читаемым.

## Mobile

Примерная ширина:

до 768px.

Особенности:

- hamburger menu;
- вертикальная композиция;
- Hero перестраивается;
- Services: 2 колонки;
- Portfolio: компактная горизонтальная галерея/карусель;
- Pricing: accordion;
- Booking: вертикальный список;
- Reviews: carousel/одна карточка;
- FAQ: accordion;
- Footer: вертикальный.

# 27. Типографика

Нужна комбинация двух типов шрифтов.

## Display / headings

Элегантный serif.

Используется для:

- ELORA;
- Hero heading;
- заголовков секций;
- крупных promotional headings.

Характер:

- fashion/editorial;
- тонкий;
- премиальный;
- не слишком декоративный.

## Body / UI

Современный нейтральный sans-serif.

Используется для:

- описаний;
- цен;
- кнопок;
- навигации;
- FAQ;
- отзывов;
- служебной информации.

---

# 28. UI-стиль

Все интерактивные элементы должны иметь единый язык.

### Buttons

- pill-shaped;
- тёмно-коричневые;
- светлый текст;
- небольшая стрелка;
- hover с очень мягким изменением цвета/светимости.

### Cards

- border-radius примерно 12–18px;
- тонкая тёплая граница;
- минимальная тень;
- background близкий к ivory.

### Images

Все фотографии:

- качественные;
- editorial beauty;
- тёплая цветокоррекция;
- натуральные оттенки кожи;
- rounded corners.

### Icons

Иконки тонкие, минималистичные.

Не использовать массивные разноцветные иконки.

---

# 29. Важные визуальные правила

1. Не превращать сайт в обычный шаблонный салон красоты.
2. Не использовать ярко-розовый, фиолетовый, синий или неон.
3. Не использовать тяжёлые тени.
4. Не делать карточки слишком пёстрыми.
5. Не использовать огромные декоративные элементы, которые перекрывают текст.
6. Не нарушать пропорции Hero.
7. Не делать desktop Hero слишком низким.
8. Не делать mobile-карточки слишком маленькими.
9. Сохранять большое количество воздуха между секциями.
10. Все секции должны ощущаться частью одной дизайн-системы.

# 30. Функциональные требования

Сайт должен быть не только визуальным макетом.

CTA **«Записаться»** должен вести к форме/секции записи.

CTA **«Записаться онлайн»** — к записи.

**«Все услуги»** — к полному списку услуг.

**«Смотреть все»** — к полному портфолио.

**«Скачать прайс»** — скачивание/открытие прайс-листа.

FAQ должен работать как accordion.

Mobile hamburger должен открывать мобильное меню.

Карточки услуг могут вести на страницы отдельных услуг.

# 31. Главный критерий реализации

AI-агент должен постоянно сравнивать готовый результат с четырьмя референсами.

Проверять:

- общую композицию;
- размеры блоков;
- пропорции;
- расстояния;
- размеры заголовков;
- положение изображений;
- количество карточек;
- форму карточек;
- цвета;
- border-radius;
- responsive layout;
- визуальную плотность.

**Цель — не просто сделать сайт «в похожем стиле», а максимально близко воспроизвести предоставленный дизайн как реальный production-ready сайт.**

При конфликте между общими дизайнерскими предположениями и референсом — **приоритет имеет референс**.

# 32. Референсы для AI-агента

Перед началом разработки агенту необходимо предоставить все четыре изображения:

- `ELORA_1_desktop_top.png`
- `ELORA_2_desktop_bottom.png`
- `ELORA_3_mobile_top.png`
- `ELORA_4_mobile_bottom.png`

Они являются единым визуальным референсом одной страницы.

**Важно:** первые два изображения являются продолжением друг друга по вертикали.  
Третье и четвёртое — продолжение мобильной версии.

Агент должен воспринимать их как:

`Desktop Top → Desktop Bottom`

и

`Mobile Top → Mobile Bottom`.

# 33. Production implementation rule

Этот документ описывает внешний вид. Все описанные секции должны быть реализованы настоящими Razor/HTML компонентами, а не статической картинкой.

Не использовать референс как единственное содержимое страницы. Изображения референсов используются AI-агентом для сравнения дизайна, а не как готовый background всей страницы.

Каждый интерактивный элемент должен иметь рабочее поведение.
