## 1. Выкладка

```
bash tools/deploy_to_host.sh
```

Скрипт делает: пробный прогон (показывает, что зальётся и что удалится на сервере) →
остановка с подтверждением → заливка → скачивание файлов обратно и сверка `sha256`.

Есть режим без остановки — `bash tools/deploy_to_host.sh --yes`. Он нужен, когда выкладку
запускаю я, а не ты: без него скрипт встаёт на `read`, ввод приходит пустой и заливка
не начинается. Список изменений в этом режиме всё равно печатается, просто без паузы.

Пароль FTP скрипт не пишет ни в файлы, ни в историю: берёт из `ELORA_FTP_PASSWORD`
или из `tools/_ftp.env`.

## 2. Обязательный шаг ПОСЛЕ заливки

**Часы работы в подвале и на страницах берутся из базы, а не из кода.** Значение в базе
перекрывает значение по умолчанию, поэтому правка в `Seed.cs` на боевом сайте ничего
не изменит.

Сейчас в боевой базе: `Site.WorkHours = «Ежедневно 09:00 – 21:00»`.
График мастеров при этом Пн–Сб 09:00–19:00, Вс — выходной. Это то самое противоречие
из блока 4 — если его не поправить, после заливки оно останется на месте.

Что сделать: `/admin/settings` → поле «Часы работы» → заменить на

```
Пн–Сб 09:00 – 19:00, Вс — выходной
```

Затрагивает подвал (все страницы), `/contacts`, `/about`, `/rules` и ответы
AI-консультанта. Проверка после правки:

```
curl -s https://elora2026.runasp.net/ | grep -c "Ежедневно"   # должно быть 0
```

## 3. Откат

```
bash tools/rollback_host.sh
```

Источник отката — папка `_upload_elora_prev`: копия той сборки, что лежит на сервере
прямо сейчас. Скрипт делает: пробный прогон → подтверждение → заливка → сброс журнала
заливки → скачивание файлов обратно и сверка `sha256` → проверка, что сайт отвечает.
В конце печатает итог одной строкой и возвращает код 1, если что-то не сошлось.

Откат запускается **только из терминала**: если ввод не с клавиатуры, скрипт отказывается
работать. Это защита от случайного запуска конвейером — вернуть боевой сайт на прошлую
сборку молча хуже, чем не вернуть вовсе.

### Чем подтверждено, что бэкап годится

1. **Сверка с журналом заливки** `tools/_upload_state.json`: `sha256` файлов в
   `_upload_elora_prev` совпадают с хешами того, что заливалось в прошлый раз
   (`ELORA.Web.dll`, `site.css` и её сжатые версии, `staticwebassets.endpoints.json`).
2. **Пробный прогон против живого хостинга** из папки `_upload_elora_prev`:
   **залить 0, удалить 0** — то есть она совпадает с текущим содержимым сервера
   по всем 116 файлам. Это прямая проверка, а не косвенная.

### Ловушка, из-за которой откат мог бы не сработать

`sync_ftp.py` решает «файл уже на сервере» по размеру и по хешу из журнала.
После отката в журнале под ключом папки `_upload_elora` остаются хеши **новой** сборки,
хотя на сервере уже старая. Тогда следующая выкладка новой сборки для файлов, у которых
совпал размер, сказала бы «уже залито» и пропустила их — на сервере осталось бы старое.
`rollback_host.sh` поэтому снимает запись журнала для папки новой сборки: пусть лучше
зальёт лишнее, чем промолчит.

Вторая ловушка — форма пути. В Git Bash путь выглядит как `/d/ELORA/_upload_elora`,
а ключ в журнале записан как `D:/ELORA/_upload_elora`; python превратил бы первый
в `D:/d/ELORA/_upload_elora`, ключ не совпал бы, и сброс молча ничего не сделал.
Проверено на копии журнала: с точным путём снимается ровно одна запись, с косым — ноль.
Скрипт переводит путь через `cygpath -m` и дополнительно умеет искать запись по имени папки.

### Чего откат НЕ возвращает

Базовые данные: записи клиентов, настройки, заявки. Выкладка их не касается — папки
`App_Data`, `logs` и `.well-known` синхронизация не трогает. Откат возвращает только код
и статику.

Команда разом:

```
bash tools/verify_deploy.py
```

Отдельно про `manifest.json`: `application/json` — не тот тип, что советует спецификация
(`application/manifest+json`). Браузеры такой манифест принимают, но Chrome пишет
предупреждение в консоль. Чтобы отдать правильный тип, нужен либо файл `web.config`
с MIME-картой (на IIS), либо свой эндпоинт вместо статики. Оставлено как есть:
на работу «Установить приложение» не влияет.

## 5. Чего в этой выкладке нет

- **Растяжки «Скидка 10% на первый визит»** — то же обещание, что убранное «24/7»:
  выполнить его некому. Оставлено, решение за владельцем.
- **Всплывающего баннера-пометки на главной** — по просьбе владельца пометка сделана
  тихой строкой внизу подвала, баннер не делался.
- **`'unsafe-inline'` в CSP** — снимается только через nonce для инлайновых скриптов,
  это отдельная работа.
- **Заголовков `Server` и `X-Powered-By` от IIS** — приложение свои не отдаёт
  (`AddServerHeader = false`), но IIS добавляет свои; убираются в `web.config`,
  на бесплатном тарифе не проверял.
