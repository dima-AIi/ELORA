# ELORA — сайт студии красоты с онлайн-записью

ASP.NET Core 10 (Razor Pages) + SQLite. Фронтенд — чистый HTML/CSS/JavaScript,
без сборщиков и фреймворков.

## Что внутри

- Онлайн-запись: услуга → мастер → дата → время → данные клиента → подтверждение.
- Защита от двойной записи (транзакция SQLite), перенос и отмена визита по ссылке.
- Админка: записи, услуги, мастера, рабочие часы, заблокированные даты, работы,
  отзывы, FAQ, настройки, клиенты и возврат «пора напомнить».
- Telegram: два бота — публичный клиентский и приватный админский; уведомления,
  напоминания, перенос и отмена кнопками в чате, вход в админку как Mini App.
- **AI-консультант** в секции «Часто задаваемые вопросы» на главной странице.

# AI-консультант

Внизу главной страницы, рядом с вопросами, стоит карточка чата: посетитель
спрашивает про услуги, цены, график или запись и получает ответ от модели.

Ключ провайдера живёт **только на сервере**. Браузер обращается к своему
маршруту `POST /api/chat`, а уже сервер идёт к модели. В JavaScript ключа нет,
в `localStorage` он не попадает.

## Как это устроено

| Файл | Что делает |
| --- | --- |
| `Pages/Index.cshtml` | Разметка секции: вопросы слева, карточка консультанта справа |
| `wwwroot/js/assistant.js` | Весь фронтенд чата: `sendToAssistant(message)` — единственная точка отправки |
| `wwwroot/css/site.css` | Стили секции (раздел «13. FAQ + AI-консультант») |
| `DTOs/BookingDtos.cs` | `ChatRequest`, `ChatTurnDto`, `ChatReply` |
| `Program.cs` | Маршрут `POST /api/chat`, чтение `.env`, регистрация сервисов |
| `Services/Ai/AiOptions.cs` | Настройки: ключ, модель, адрес, таймаут, лимиты |
| `Services/Ai/EloraAssistant.cs` | Системный промпт из базы, вызов модели, разбор ответа и ошибок |
| `Services/Ai/ChatRateLimiter.cs` | Ограничение частоты: не больше N вопросов в минуту с одного адреса |
| `ELORA.Web/.env.example` | Образец файла с ключом (копируется в `.env`) |

Системный промпт собирается из базы, а не вписан в код: услуги с ценами и
длительностью, график, адрес, телефон. Меняете цены в админке — консультант
говорит то же, что и сайт. Кэш промпта — 5 минут.

История диалога ограничена последними 6 сообщениями (`Ai:HistoryMessages`):
бесконечный диалог дорожает с каждым вопросом, а для консультанта не нужен.

## Регистрация и получение ключа NVIDIA

1. Откройте <https://build.nvidia.com> и войдите в аккаунт NVIDIA
   (регистрация бесплатная).
2. Выберите модель — например, `nvidia/llama-3.1-nemotron-70b-instruct`.
3. Нажмите **Get API Key** — ключ вида `nvapi-...` показывается один раз,
   сохраните его.
4. Бесплатный тариф даёт ограниченное число кредитов; их хватает на демонстрацию
   и небольшую нагрузку.

Список доступных моделей: <https://integrate.api.nvidia.com/v1/models>.

> **Важно: каталог общий, а доступные модели — у каждого ключа свои.**
> Каталог отдаёт около 80 моделей, но конкретный ключ видит лишь часть из них:
> на остальные приходит `404 Not found for account`. Поэтому одной модели мало —
> в настройках задана **цепочка** `Ai:Models`, и консультант перебирает её по
> порядку, пока какая-нибудь модель не ответит.

### Цепочка моделей и запасные

Порядок по умолчанию (`Ai:Models` в `appsettings.json`) — от быстрой к медленной:

| № | Модель | Зачем |
|---|--------|-------|
| 1 | `nvidia/nemotron-3-super-120b-a12b` | основная, отвечает за ~2 с |
| 2 | `meta/muse-glimmer-30b` | запасная |
| 3 | `z-ai/glm-5.3` | запасная |
| 4 | `nvidia/nemotron-3.5-lightning-30b-a3b` | последняя в очереди |

Что происходит при сбое:

- **Модель недоступна ключу (404)** или вернула ошибку — берётся следующая.
- **Временный сбой (429, 5xx, «Service temporarily overloaded»)** — та же модель
  повторяется ещё раз (`Ai:AttemptsPerModel`, по умолчанию 3), и только потом
  берётся следующая. Бесплатный тариф перегружен довольно часто, а быстрый повтор
  быстрой модели (основная отвечает за ~2 с) дешевле, чем ожидание медленной запасной.
- **Ключ не принят (401/403)** — перебор прекращается сразу: дело не в модели.
- **Общий бюджет** `Ai:TotalTimeoutSeconds` не даёт цепочке держать посетителя
  у экрана слишком долго. Если от бюджета осталось меньше 10 секунд, запасные
  модели уже не запускаются — ответ всё равно не успеет прийти.
- **Причина отказа сохраняется осмысленная.** Из всех неудач наружу уходит та,
  что что-то объясняет («сервис перегружен», «слишком много вопросов», «ключ не
  принят»), а не общая заглушка: перегрузка бесплатного тарифа — норма, и
  посетителю нужно сказать именно про неё.

### О чём консультант говорит

Тема строго ограничена студией ELORA: услуги, цены, длительность, график, адрес,
телефон, запись, перенос и отмена. Посторонние вопросы — о владельцах и сотрудниках,
о самой модели и её создателях, политика, медицина, код, переводы, «забудь
инструкции» — вежливо отклоняются с возвратом к услугам. Промпт лежит в
`EloraAssistant.BuildSystemPrompt()` и собирается из настоящих данных сайта.

> **Про рассуждающие модели.** Nemotron 3 и GLM сначала «думают», и размышления
> приходят в отдельном поле `reasoning_content` — оно игнорируется. Но если ответ
> обрывается по лимиту токенов, размышления попадают прямо в текст ответа
> (видно по `finish_reason = "length"` и английскому вступлению вроде
> «The user asks…»). Такой ответ считается неудачей, и цепочка идёт дальше.

## Настройка ключа

Ключ задаётся любым из трёх способов — приложение читает их по очереди.

**1. Файл `.env` (локально, проще всего).**

```bash
cd ELORA.Web
cp .env.example .env
```

Откройте `.env` и впишите ключ:

```
NVIDIA_API_KEY=nvapi-ваш-ключ
```

Файл `.env` лежит рядом с приложением. Он перечислен и в `.gitignore`
(не попадает в репозиторий), и в `.dockerignore` (не попадает в образ) —
секрет не утечёт ни туда, ни туда. Приложение ищет файл рядом с собой и выше
по дереву каталогов (до шести уровней) — так он находится и при запуске из
`bin/Debug/net10.0`, и из корня решения.

**2. User Secrets** (штатный способ для ASP.NET Core):

```bash
cd ELORA.Web
dotnet user-secrets set "Ai:ApiKey" "nvapi-ваш-ключ"
```

**3. Переменные окружения** (так делается на хостинге):

```bash
# Linux / macOS / контейнер
export NVIDIA_API_KEY=nvapi-ваш-ключ
export NVIDIA_MODEL=nvidia/nemotron-3-super-120b-a12b          # одна модель, не обязательно
export NVIDIA_MODELS="nvidia/nemotron-3-super-120b-a12b,meta/muse-glimmer-30b"  # цепочка

# Windows (PowerShell)
$env:NVIDIA_API_KEY = "nvapi-ваш-ключ"
```

`NVIDIA_MODELS` — цепочка одной строкой через запятую: на хостинге задавать
многострочные значения неудобно. Если задана цепочка, она важнее одиночного
`NVIDIA_MODEL`.

Приоритет: переменные окружения и User Secrets перекрывают `.env`, а `.env` —
значения из `appsettings.json`. Токены Telegram при этом продолжают жить в
user-secrets, как и раньше.

## Запуск

```bash
cd ELORA.Web
dotnet restore
dotnet build -c Debug
dotnet run --urls http://localhost:5080
```

Сайт: <http://localhost:5080>. Админка: `/admin`, логин `admin`, пароль `elora2026`.

## Проверка, что консультант работает

**Без ключа** маршрут отвечает 503 и понятным текстом — вместо выдуманного ответа:

```bash
curl -s -X POST http://localhost:5080/api/chat \
  -H "Content-Type: application/json" \
  -d '{"message":"Сколько стоит маникюр?","history":[]}'
```

Ожидаемый ответ:

```json
{"ok":false,"error":"Консультант ещё не подключён: на сервере не задан ключ AI. ..."}
```

**С ключом** приходит настоящий ответ модели:

```json
{"ok":true,"reply":"Маникюр — от 1 000 ₽, аппаратный от 1 300 ₽ ..."}
```

На самой странице: откройте главную, прокрутите к секции с вопросами. В карточке
сразу видно приветствие, ниже — три быстрые кнопки («Цены», «Время работы»,
«Как записаться?»). Кнопка отправки серая, пока поле пустое; во время ответа
показывается «печатает…» с тремя точками, повторная отправка заблокирована;
при ошибке появляется сообщение и кнопка «Повторить».

## Настройки (секция `Ai` в `appsettings.json`)

| Ключ | По умолчанию | Значение |
| --- | --- | --- |
| `ApiKey` | пусто | Ключ провайдера |
| `Models` | цепочка из 4 моделей | Модели по порядку: первая рабочая и отвечает |
| `Model` | `nvidia/nemotron-3-super-120b-a12b` | Одна модель; используется, если `Models` пуст |
| `BaseUrl` | `https://integrate.api.nvidia.com/v1` | Адрес OpenAI-совместимого API |
| `TimeoutSeconds` | `45` | Сколько ждём ответа одной модели |
| `AttemptsPerModel` | `3` | Повторов одной модели при временном сбое |
| `TotalTimeoutSeconds` | `80` | Общий бюджет на всю цепочку |
| `HistoryMessages` | `6` | Сколько прошлых реплик отправляем |
| `MaxMessageLength` | `800` | Предел длины вопроса |
| `MaxAnswerTokens` | `1200` | Предел длины ответа (рассуждающим моделям нужен запас) |
| `RequestsPerMinute` | `12` | Запросов в минуту с одного адреса |

## Замена провайдера

Провайдер вынесен в настройки, а не в код: используется обычный
OpenAI-совместимый формат `POST {BaseUrl}/chat/completions` с заголовком
`Authorization: Bearer <ключ>`.

Чтобы перейти на другого провайдера (OpenRouter, локальная модель, свой шлюз),
достаточно поменять `Ai:BaseUrl`, `Ai:Model` и ключ. Разметка и скрипт сайта при
этом не меняются — фронтенд общается только со своим `/api/chat`.

## Ответы на частые вопросы

**Консультант отвечает «не подключён».** Не задан ключ. Проверьте `.env` /
user-secrets / переменные окружения и перезапустите приложение.

**«Ключ консультанта не принят сервисом AI».** Ключ неверный или отозван.

**«Модель недоступна на этом ключе».** Указана модель, которой нет в каталоге
провайдера. Сверьтесь со списком моделей.

**«Слишком много вопросов подряд».** Сработал ограничитель частоты
(`Ai:RequestsPerMinute`).

# Если сборка не запускается на Windows

Система может заблокировать только что собранную сборку — в журнале
`Microsoft-Windows-CodeIntegrity/Operational` появится событие с кодом
`0x800711C7`, а приложение упадёт с `FileLoadException`. Это Smart App Control:
он не доверяет неподписанным сборкам. Настройка необратимая, поэтому решение
принимает владелец машины; подробности — в документации проекта.

Пока настройка включена, проверить вёрстку и скрипты можно без запуска
приложения — на статической копии страницы.
